# AOT 与目标平台改造执行报告（2026-10-19）

## 范围

依据前次只读分析及本次实施授权，修改 AOT 阻碍、三平台发布配置、目标平台判定和相关回归测试；追加修复设置页 GitHub 超链接样式。没有扩展到下载器、并发、任务管理等无关重构，也没有覆盖工作区原有的相关未提交改动。

环境：Windows x64，.NET SDK 10.0.402，目标 net10.0，Avalonia 11.3.18。原分析报告路径为 `F:/dos/AOT与代码质量分析报告-20261018.md`；最终判断以实际项目、还原资产、编译诊断和发布产物为准。

## 1. 实际 UI 与序列化修复

### XAML 编译绑定

- `AvaloniaUseCompiledBindingsByDefault` 移至真正编译 XAML 的 `OneLauncher.csproj`，不再仅设置在 Desktop 入口项目。
- `MainWindow.axaml` 的侧栏元素引用显式使用 CompiledBinding（8 处）。
- `Shells.axaml` 明确 PageShell/PaneHeader 的 ControlTemplate.TargetType；PageShell 使用面向 TemplatedParent 的编译绑定，保留 IsPaneOpen 双向回写、正文禁用和遮罩显隐行为（3 处）。
- `App.axaml` 的编辑菜单不再借助反射绑定和跨 Popup 的祖先查找来调用 TextBox 方法（原来 5 处）。新增附加属性 `TextBoxEditMenu.Enabled`，为每个 TextBox 单独创建菜单，以静态委托调用 Copy/Cut/Paste/SelectAll。
- 菜单打开时重新计算选区、密码和只读权限。实际验证发现 Avalonia 11 的 CanCut/CanPaste 并不在每次 IsReadOnly 变化时刷新，因此不能直接缓存它们。兼顾用户右键打开和程序直接 Open() 两条路径；已有自定义菜单不会被覆盖。

### 裁剪与数据读写

- 删除 Desktop 对 Avalonia.Controls、Avalonia.Themes.Fluent 的整程序集保留，以及 TextBox 方法的 root descriptor 引用；由真实编译绑定和静态调用保证可达性。旧 XML 文件不再参与构建。
- `BasicDataManager<T>` 的异步读写改用 `JsonTypeInfo<T>` 重载。AccountManager、DBManager、GameDataManager 返回各自源生成上下文的具体元数据，避免只配置 TypeInfoResolver 却仍调用标注 RequiresDynamicCode/RequiresUnreferencedCode 的泛型 options 重载。
- 保留 JSON 字段名称、嵌套模型、反序列化 ID 修复、默认值及 Debug/Release 缩进约定，没有趁此改写文件存储策略。
- 修复实际新发现的 `SystemMemoryHelper` 中 `Marshal.SizeOf(Type)`，改用 `Marshal.SizeOf<MEMORYSTATUSEX>()`。

### GitHub 链接追加修复

- `Label.axaml` 的 link-button 在普通、悬浮、按压时均保持透明；悬浮/按压文字为紫色，深色主题使用更亮的紫色。
- 移除 `8,5` 内边距和按钮最小尺寸，明确同行垂直居中；设置页以 `Content="GitHub"` 使用该样式，保留原 OpenGithubCommand。
- 验证真实设置页的模板 ContentPresenter，而非仅检查 Button.Background；Fluent 模板状态可能覆盖后者。
- 没有移除键盘焦点机制，也没有在测试中启动浏览器。

## 2. 目标平台模型重做

旧问题不是简单把 `#if WINDOWS` 换个名称：PackageReference 可能先根据宿主系统选了包，之后才在 targets 阶段依据 RID 改编译常量；项目引用还依赖改写 `_MSBuildProjectReferenceExistent.SetTargetFramework`，导致还原图、条件编译和依赖图不一致。

新链路：

```text
已知 PublishProfile（提前导入每个项目）或显式 -r
  → RuntimeIdentifier
  → build/TargetPlatform.props 的 OneLauncherTargetOS
  → Core 平台专属包条件 + Directory.Build.targets 的 ONELAUNCHER_TARGET_* 常量
  → 所有项目引用的目标分支一致
```

- 统一使用项目专用 `ONELAUNCHER_TARGET_WINDOWS/LINUX/MACOS`，移除各 csproj 的宿主平台条件常量。
- Windows MSAL Broker 包在 restore 求值之前按目标 OS 选择，不会因为“在 Windows 上构建 Linux”而错误进入依赖图。
- 仅对含平台分支的 UI/Core/Console 类库声明 IsRidAgnostic=false。删除事后改写 SDK 内部项目引用元数据的 target；已知配置会在完整引用图内自行导入相同属性。
- 仅不带 RID 的本机 Debug 开发允许宿主回退。Release/ReleaseAot 必须有 RID；所有 publish 包括 Debug publish 都必须明确 RID。
- 拒绝不支持的 RID、配置平台与 RID 冲突、AOT/JIT 配置与 PublishAot 开关冲突。
- 支持 win/linux/osx 的 x64/arm64 RID。Minecraft 下载库、启动类路径及 JVM 规则的架构判断统一使用进程架构，消除“macOS 一定 arm64、Windows/Linux 一定 x64”的固定假设；这不意味着已实现任意架构 Java 的独立选择模型。

## 3. 六份配置与发布保护

| 平台 | AOT | JIT | 默认 RID |
| --- | --- | --- | --- |
| Windows | WindowsAot.pubxml | WindowsJit.pubxml | win-x64 |
| Linux | LinuxAot.pubxml | LinuxJit.pubxml | linux-x64 |
| macOS | MacOSAot.pubxml | MacOSJit.pubxml | osx-arm64 |

配置位于 `OneLauncher.Desktop/Properties/PublishProfiles`。默认 Release、自包含、目录发布，按 RID/模式分开输出。AOT 开启裁剪；JIT 关闭裁剪、AOT 与 ReadyToRun。可通过 -r 覆盖同系统架构。

`NativeAotSingleFile` 已退役为 WindowsAot 目录式发布兼容别名；不再执行自制 DLL 打包与启动时解压。旧 bootstrap 模板不参与发布。不能把它或这些新配置描述为“仅一个 EXE、无需原生 DLL”。

新增 `build/PublishValidation.targets`：

1. 检查 NuGet 导入的 ILCompiler 编译链及 NativeCompilationDuringPublish，防止 `PublishAot=true` 但没有运行原生编译的假成功。
2. 不压制裁剪诊断，并将链接器/原生编译器诊断设为错误。
3. Publish 完成后检查原生入口存在，拒绝混入 CoreCLR、clrjit 或入口托管 DLL 的输出目录。

这些是构建一致性与产物检查，不等同于全部业务、所有原生库及所有架构运行验收。应分发整个发布目录。

全局 SDK 从允许跨 feature band 漂移改为 10.0.402/latestPatch；CI 读取同一 global.json。
GitHub Actions 改为三平台 × AOT/JIT 六任务，runs-on 使用实际矩阵系统，RID 架构匹配 runner；Linux AOT 安装 clang/zlib 开发依赖。每个任务发布真实应用及同模式 headless 测试并执行测试。

## 5. 明确未宣称完成的事项

- 当前只有 Windows 原生工具链；Linux/macOS Native AOT 的原生链接和目标系统运行仍需对应 CI 或实体机器确认。本次没有启动远端 CI，也未提交/推送代码。
- ARM64 RID 可选择不代表已逐平台/逐架构验收，尤其 Windows ARM64 的 MSAL Broker 必须单独验证。
- 没有执行真实 Microsoft 登录、游戏启动或全部页面人工测试；headless 回归不能替代这些业务验收。
- 不处理与 AOT 无关的既有 C# 可空性、命名、MVVM 告警，以及参数化窗口的 Avalonia AVLN3001 资源提示；不会把“没有 AOT 告警”说成“整个仓库零告警”。
