# Forge 局部实现与验证说明

日期：2026-10-22。依据同目录《Forge采样版本支持行动报告-局部改造与安装实验-20261022》实施。本说明记录代码行为与已执行检查，不将处理器成功等同于游戏验收完成。

## 实现结构

沿用 Download Provider → ForgeSeriesInstallTasker 和 Launcher Strategy 两条入口。没有新增全局服务、修改实例模型或改变现有版本槽位：配置仍存放于 `versions/<Minecraft>/version.forge.json` 或 `version.neoforge.json`。

`Mod/ModLoader/forgeseries` 下按协议职责拆分：

| 目录 | 职责 |
| --- | --- |
| Installation | 安装输入快照、归档分型、Maven 路径约束、摘要校验与文件替换 |
| Legacy | 读取旧安装器 `install` 和 `versionInfo` |
| Profiles | 读取 spec 0/1 profile 引用的版本 JSON |
| Processors | 客户端占位符解析、处理器进程、退出码及 outputs 校验 |
| Launch | 条件参数、旧参数分词、加载器增量参数、单参数编码 |
| JarMod | 明确报告旧 JarMod 的未完成前置条件 |

目录按包内协议区分，不按 Minecraft 版本号复制安装流程。后续协议差异应增加对应解析或执行分支，继续输出同一个安装快照。

## 安装行为

准备阶段读取安装器并核对 Minecraft、加载器身份、库坐标和引用路径，返回远程依赖；此时不发布版本配置。旧版的 universal 和新版内嵌 Maven 构件从归档提取，不发送空 URL 请求。`clientreq: false` 的服务器专用库被排除；零客户端处理器是合法情况，未使用的安装工具依赖不混入运行库。

安装阶段在独立临时目录准备原版副本与完整依赖，校验缓存并修复不合格文件，然后按清单顺序运行客户端处理器。使用 `ProcessStartInfo.ArgumentList`，同时读取 stdout/stderr，以退出码判断进程失败；声明的 outputs 必须通过摘要检查才能跳过，未声明 outputs 的步骤仍执行。取消时终止处理器并等待输出读取结束。

现代样本的 Mojang mappings 可通过已有版本元数据下载，按 URL、长度和 SHA-1 校验。生成的 slim、extra、patched 等已知产物再作检查；依赖和生成库校验完成后复制到 libraries，最后替换版本 JSON。失败时释放本地安装锁并清理本次临时目录。

该顺序不能保证整个下载、全量 libraries 和版本登记的跨文件事务；现有公共下载行为仍可能提前写库。仍只支持同一 Minecraft/加载器的单配置槽位。

Java 8 在本机含中文的 classpath 下无法加载处理器，改用系统临时目录运行后，含中文及空格的游戏根目录测试通过。若系统临时目录自身含无法被 Java 8 表达的字符，仍需额外验证，不能由此次结果推断所有路径均受支持。

## 启动与身份判断

旧安装器使用 `minecraftArguments`，Strategy 仅追加 `--tweakClass`，公共账户和路径参数继续由既有 Builder 生成。现代 profile 保留 game/jvm 的条件规则、模块参数及占位符替换。运行库保留 classifier 区别，使用与既有 Builder 兼容的覆盖键，并检查运行库文件是否存在。

`ModLoaderDetector` 综合主类、加载器自身 Maven 构件及 tweak/fml 参数判断身份。普通 Forge 共用库不能单独证明 Forge 身份；早期 NeoForge 构件优先于其共存 Forge 库。共享 BootstrapLauncher/ModLauncher 缺少证据时明确失败，不能误判为原版。不同加载器的冲突证据也会失败。

`Tools.MainClassToModEnum` 保留原有单参数调用形式，并允许提供库与游戏参数。PCL 唯一调用点通过 `PclVersionInspector` 收集继承链证据、解析基础版本；缺父版本、循环或过深继承、缺主类和身份歧义有明确错误。这只改进识别，不承诺保留 PCL 原实例的精确加载器构建；后续安装仍沿用原有导入流程。

## 验证结果

`tests/OneLauncher.ForgeTests` 是独立控制台 fixture runner，不初始化 UnitedCore，不操作用户游戏数据。HTTP handler 仅返回本地保存的官方输入；处理器实际通过本机 Java 8/17 执行。

| 检查 | 本次结果 |
| --- | --- |
| Forge 1.7.10、1.8.9、1.12.2 | 完成实际安装、内嵌产物摘要比对与 Strategy 参数/库检查 |
| Forge 1.16.5、1.19.2、1.20.1 | 完成实际客户端处理器、已知生成产物 SHA-1 比对与 Strategy 检查 |
| 六样本含中文和空格游戏根目录 | 通过，原版 JAR 摘要不变 |
| NeoForge 1.20.1 / 20.2.93 | 官方包解析、身份及客户端处理器选择通过；未进行实际 NeoForge 安装 |
| 失败、取消、重试 | 使用 Java 测试处理器验证：失败保留旧配置，取消收尾进程，重试可重新获取锁 |
| outputs 与参数 | 有效输出跳过；坏输出重建；无 outputs 继续执行；循环/未知占位符、目录越界、未知 spec 被拒绝 |
| PCL 继承与识别 | 自定义名称、旧 tweak 参数、NeoForge 共存库、缺父版本、循环、缺主类及歧义检查通过 |
| 汇总 | 113 项断言通过 |
| 编译 | ForgeTests 与 OneLauncher 前端编译通过；项目编译仍有警告 |

复现前需要研究目录中的官方输入、基准安装库和 `extra-libraries`。Java 路径固定为本机 Eclipse Adoptium Java 8/17；其他机器需调整。运行命令：

```powershell
dotnet build tests/OneLauncher.ForgeTests/OneLauncher.ForgeTests.csproj --nologo -v minimal -clp:ErrorsOnly
dotnet tests/OneLauncher.ForgeTests/bin/Debug/net10.0/OneLauncher.ForgeTests.dll
dotnet build OneLauncher/OneLauncher.csproj --nologo -v minimal -clp:ErrorsOnly
```

测试入口增加异常捕获，失败输出完整异常并返回 1。另以不存在的 fixture 路径验证此失败路径，正常输出 FAIL 并返回 1。截图中的 `dotnet.exe` 应用错误尚未取得与当前运行对应的异常栈；不能仅凭 `0xe0434352` 归因为 .NET runtime 缺陷。
